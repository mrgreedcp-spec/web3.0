# 清洗日志

**每处改动记一行：哪一步、哪条记录、做了什么、改前、改后、为什么。**清洗后的数据只告诉你结果，清洗日志告诉你结果是怎么来的。

## 字段
| 字段 | 例子 |
|---|---|
| step | 4 |
| batch_id | SIM-20261005-L1 |
| action | run_hours 改为缺失 |
| before | 0 |
| after | 空 |
| reason | 有 1135.1 kg 产出却记 0 小时，前后矛盾，视为记录错误 |

## 要点
- 用脚本自动写，不要手工记
- 靠假设做的改动，reason 里写明“【假设】”，见 [[假设与待确认]]
- 除了日志，数据本身也加标记列（`issue_flags`），打开数据就能看到哪行有问题
- 校验时检查“有标记的行都写进了日志”，见 [[验收标准与 assert]]

## 例子
[[项目 · 模拟批次数据]] 的日志共 9 条，和问题清单的 9 处问题一一对应。
