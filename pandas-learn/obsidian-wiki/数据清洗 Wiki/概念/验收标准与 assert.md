# 验收标准与 assert

**把“数据干净了”写成一条条可以检查的条件，再写成 assert：条件成立就放行，不成立就报错停下。**

## assert 是什么
```python
assert 条件, "条件不成立时显示的提示"
```
Python 的关键字，中文叫“断言”。像流水线上的质检员：合格就放行，不出声；不合格就立刻停线。

## 好的验收标准
- 能检查：“共 60 个批次”，而不是“数据干净了”
- 每条对应一个清洗步骤
- 包括“原始文件没被改动”

## 例子：模拟批次数据的 10 条
1. 原始文件的 SHA-256 不变
2. 每行都标注 `SIMULATED`
3. 共 60 个批次
4. 批次号唯一
5. 除取消批次外，没有运行时间为 0 的行
6. 合格产出不超过投入
7. 派生指标里没有 inf
8. 有标记的行都写进了 [[清洗日志]]
9. **行数对账**：原始行数 = 现在的行数 + 日志里删除的行数
10. **每个问题都按计划处理**：问题清单和清洗日志逐条对账

## 只检查结果，不够
最初只有前 8 条。做实验时故意**跳过去重那一步**，8 条居然全部通过：后面按批次号去重时，把整行重复“顺手”删掉了，行数和主键都对，但日志把它们错记成了“冲突记录（假设）”。

加上第 9、10 条以后，这个实验会报出：
```
计划了但没按计划处理：[('SIM-20261002-L3', 'R1'), ('SIM-20261010-L1', 'R1')]
处理了但不在计划里：[('SIM-20261002-L3', 'R2'), ('SIM-20261010-L1', 'R2')]
```
**校验不仅要检查最终结果对不对，还要检查每个问题是不是按计划的方式处理的。**

## 一次报出所有失败
先把每一条检查的结果都算出来、打印出来，最后统一判断：
```python
failed = [name for name, ok in checks.items() if not ok]
assert not failed, f"校验失败：{failed}"
```
不要每算一条就 assert 一次，否则第一条失败就停了，后面的问题看不到。

## 为什么不用 print 看
print 要靠人看，容易漏；assert 由机器判断。数据更新或脚本改动后重跑一次，有问题立刻报错。

## 注意
用 `python -O` 运行时会跳过所有 assert。生产程序里重要的检查写成 `if ...: raise ValueError(...)`。
