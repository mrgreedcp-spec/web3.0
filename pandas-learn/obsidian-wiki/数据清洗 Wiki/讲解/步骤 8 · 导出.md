# 步骤 8 · 导出

**校验全部通过后才导出。清洗结果和日志另存为新文件，原始文件不动。**

## 知识点
1. 导出前去掉只在清洗过程中用的辅助列 `raw_line`
2. 按日期、产线排序，方便阅读
3. `to_csv(..., index=False)`：不把行索引写进文件
4. 日志用 `encoding="utf-8-sig"`：用 Excel 打开中文不乱码
5. 只有完整运行（不加 `--step`，或 `--step 8`）才会导出

## 结果
| 文件 | 内容 |
|---|---|
| `batches_clean_SIMULATED.csv` | 60 行 × 15 列：原始 8 列 + `issue_flags`、`cancelled`、`ok_for_efficiency` + 4 个指标 |
| `cleaning_log.csv` | 9 条改动记录 |
| `batches_raw_SIMULATED.csv` | 未改动 |

## 读回来时：CSV 不保存类型
| 列 | 直接 `read_csv` 读回 | 要恢复成什么 |
|---|---|---|
| `date` | 文本 `str` | `parse_dates=["date"]` |
| `line` | 文本 `str` | `dtype={"line": "category"}` |
| `issue_flags` | 空白读成 **NaN**（53 个） | `.fillna("")` 恢复成空字符串 |
| `cancelled`、`ok_for_efficiency` | 布尔 `bool` ✓ | 不用处理 |

```python
c = pd.read_csv(path, parse_dates=["date"], dtype={"line": "category"})
c["issue_flags"] = c["issue_flags"].fillna("")
```

## 可以复现
再跑一次，导出的两个文件和上次的 SHA-256 完全一样：同样的输入、同样的脚本，得到同样的结果。

## 只有日志带 BOM
日志用 `utf-8-sig` 写出，文件开头多 3 个字节（BOM），Excel 靠它识别 UTF-8，打开中文不乱码。清洗后的数据没加 BOM，主要给程序读；要用 Excel 打开，也可以改成 `utf-8-sig`。pandas 读这两种文件都没问题。
