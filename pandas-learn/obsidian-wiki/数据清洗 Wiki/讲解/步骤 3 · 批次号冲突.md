# 步骤 3 · 批次号冲突

**同一个批次号有两条记录、数值不同：有确认结果就按确认表处理，没有才按假设保留一条，并在数据和日志里留痕。61 行 → 60 行。**

> 更新（2026-11-05）：Q1 已确认 840.9 正确，现在按确认表保留原始第 54 行。下面的推演记录的是**最初按假设处理**的过程，保留下来作为教训。

## 知识点
1. `df["batch_id"].duplicated(keep=False)`：只按一列查重复
2. 必须先完成 [[步骤 2 · 删除整行重复]]，剩下的批次号重复才是真正的冲突
3. `keep="last"` 保留后录入的，**这是一个假设**
4. `is_unique`：处理完以后验证主键唯一
5. 靠假设做的处理，**在两处留痕**：`issue_flags` 标记 + 日志写“【假设】”
6. **用数据检验假设**：把候选值放进同产线的正常范围里比较
7. 数据检验不能代替确认，见 [[假设与待确认]]

## 推演过程
1. **现状**：SIM-20261017-L3，第 54 行合格产出 840.9，第 55 行 800.9，其他字段相同
2. **假设**：后录入的是更正后的数据 → 保留 800.9
3. **代码**
   ```python
   drop = df["batch_id"].duplicated(keep="last")
   df = df[~drop].copy()
   ```
4. **结果**：60 行；`is_unique` 为 True；标记 `冲突记录_按假设保留`；被删的 840.9 也写进了日志
5. **检验假设**

| 保留 | 合格率 | 和 L3 其他批次（88.6%～93.5%）比 |
|---|---|---|
| 840.9 | 89.4% | 在范围内 |
| 800.9（最初按假设保留的） | **85.1%** | **比所有批次都低** |

后来确认：生成脚本是用原值减去 40 制造出第二条记录的，原值是 840.9，**这个假设选错了**。对 L3 平均合格率的影响很小（90.58% vs 90.81%），但单看这个批次会误导人。

## 确认以后：用确认表代替假设
```python
CONFIRMED = {"SIM-20261017-L3": {"ref": "C1", "keep_raw_line": 54, "column": "good_output_kg", "value": 840.9, "source": "..."}}
```
- 有确认结果的冲突，按表保留指定行；没有的，才退回到假设
- **保护**：表里写的值必须和那一行对得上，写错成 841.0 会直接报错
- 日志从“删除冲突记录（假设）”变为“删除冲突记录（已确认）”，理由写明确认编号 C1
- 更新后 L3 平均合格率 90.58% → 90.81%，清洗结果 900 个格子里只变了 4 个
