# 步骤 7 · 校验

**10 条 assert：不仅检查最终结果，还检查每个问题是否按计划处理。**

## 知识点
1. 每条校验对应一个清洗目标，见 [[验收标准与 assert]]
2. **先算出所有检查，再统一判断**，一次报出所有失败
3. **行数对账**：原始 = 现在 + 已删除
4. **计划与日志对账**：问题清单的每一条，都要有对应的处理记录
5. **故意制造错误**，检验校验本身有没有漏洞

## 10 条校验
1. 原始文件的 SHA-256 不变
2. 每行都标注 `SIMULATED`
3. 共 60 个批次
4. 批次号唯一
5. 除取消批次外，没有运行时间为 0 的行
6. 合格产出不超过投入
7. 派生指标里没有 inf
8. 有标记的行都写进了日志
9. 行数对账：63 = 60 + 3
10. 每个问题都按计划处理

## 推演过程：用两个实验检验校验
**实验 A：故意让一个指标变成 inf** → 第 7 条 ✗，其余 ✓，报 `校验失败：['派生指标里没有 inf']`

**实验 B：故意跳过第 2 步**
- 只有前 8 条时：**全部通过**。因为第 3 步按批次号去重，把整行重复也“顺手”删了，行数和主键都对
- 但日志把两行整行重复错记成了“冲突记录（假设）”
- 加上第 9、10 条后：第 10 条 ✗，并指出
  ```
  计划了但没按计划处理：[('SIM-20261002-L3', 'R1'), ('SIM-20261010-L1', 'R1')]
  处理了但不在计划里：[('SIM-20261002-L3', 'R2'), ('SIM-20261010-L1', 'R2')]
  ```

**教训：结果对，不代表过程对。校验也需要被检验。**

## 一次报出所有失败
```python
for name, ok in checks.items():
    print(f"  {'✓' if ok else '✗'} {name}")
failed = [name for name, ok in checks.items() if not ok]
assert not failed, f"校验失败：{failed}"
```
