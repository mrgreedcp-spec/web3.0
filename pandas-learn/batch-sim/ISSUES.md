## 不处理会有什么影响

- **零运行时间**：计算 `input_kg / run_hours`（产能）或 `energy_kwh / run_hours`（每小时能耗）时，**除法本身不报错、也不提醒**，直接得到无穷大（`inf`）；接着平均值也会**悄悄变成 `inf`**，要到算标准差时才会出现 `RuntimeWarning`，结果是 `NaN`。问题在毫无提示的情况下扩散，比直接报错更危险。
- **重复记录**：投入、产出、能耗的合计都会偏高。日期越细，偏差越明显。
- **缺失值**：pandas 求和时会**默默跳过**空值，合计偏低却不会有任何提示。

## 通用体检工具与业务规则的对比

| 问题 | 通用体检工具 | 业务规则检查 |
|---|---|---|
| 缺失值 | ✅ 查出，但建议“填众数 / 中位数” | ✅ 查出，建议**找记录人补录**。生产记录不能凭空编数字 |
| 整行重复 | ✅ 查出 | ✅ 查出，并给出具体行号 |
| 批次号重复但数值不同 | ⚠️ 只提示批次号有重复，分不清是哪种重复 | ✅ 指出是哪一列不同、两个值分别是多少 |
| 运行 0 小时却有产出 | ⚠️ 只提示 `run_hours` 有 0 | ✅ 指出前后矛盾，并区分“记录错误”和“取消批次”两种情况 |
| `data_label` 整列相同 | ❌ 建议删除这一列。**这一建议是错的**：这一列是故意加的模拟标注 | ✅ 检查每行都标注了 `SIMULATED` |
| 日期还是文本 | ✅ 提示用 `parse_dates` 转换 | — |

**结论：通用工具负责找出格式问题，业务规则负责判断数据是否合理。**通用工具给出的建议，要结合业务来判断要不要采纳。
