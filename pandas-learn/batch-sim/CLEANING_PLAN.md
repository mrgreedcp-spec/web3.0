# 第一部分：本次的清洗计划

## 1. 目标与范围

| 项目 | 内容 |
|---|---|
| 数据用途 | 按产线比较合格率、产能、能耗等效率指标。**生产记录相当于“账”**：缺失值不能凭空填补，错误的值要找记录人核实 |
| 清洗对象 | `data/batches_raw_SIMULATED.csv`，SHA-256 `de9417aec2b4880c6fa9230b12b58dbf90623b7d47c40cd395c816c0df49dcee` |
| 本次范围内 | 去重、批次号冲突、零运行时间、缺失值标记、计算派生指标 |
| 本次范围外 | 不修正任何数值（只删除、标记或设为缺失）；不处理正常范围内的波动 |

## 2. 输入材料

- 数据字典：[`DATA_DICTIONARY.md`](DATA_DICTIONARY.md)
- 问题清单：[`ISSUES.md`](ISSUES.md)（9 处问题）

## 3. 逐个问题的处理决定

可选的处理方式：删除 / 修正 / 设为缺失 / 填补 / 保留并标记 / 暂不处理。

| # | 问题 | 处理方式 | 理由 | 是假设吗？找谁确认？ | 行数 |
|---|---|---|---|---|---|
| 1、2 | 整行重复（SIM-20261002-L3、SIM-20261010-L1） | 删除 | 和上一行完全相同 | 否 | −2 |
| 3 | 批次号重复且数值不同（SIM-20261017-L3：840.9 / 800.9） | 暂时保留后录入的那条 | 推测后录入的是更正后的数据 | **是假设**，找记录人确认 | −1 |
| 4–7 | 缺失值（合格产出 1、运行时间 1、能耗 2） | 保留为空，加标记 | 生产记录不能凭空编数字 | 找记录人补录 | 0 |
| 8 | 有产出却记 0 小时（SIM-20261005-L1） | 设为缺失，加标记 | 前后矛盾；但产出和能耗有效，不能删 | 找记录人核实实际时长 | 0 |
| 9 | 0 产出、0 小时（SIM-20261013-L3） | 保留，标记为取消批次 | 像取消的批次，算效率时排除 | 确认是否真的取消 | 0 |

## 4. 步骤顺序

| 步骤 | 内容 | 为什么排在这里 |
|---|---|---|
| 1 | 读取，`raw.copy()`，记下原始行号 | 一切修改都在副本上做，并且能追溯回原始文件 |
| 2 | 删除整行重复 | 先去重，否则后面的计数和平均值会重复计算 |
| 3 | 处理批次号冲突 | 去重之后剩下的才是真正的冲突 |
| 4 | 处理零运行时间 | 先把错误的 0 改成缺失，第 5 步才能一起统计 |
| 5 | 缺失值加标记 | 包括第 4 步改出来的那个 |
| 6 | 整理类型，计算派生指标 | 数据处理完再算，避免算出 `inf` |
| 7 | `assert` 校验 | 确认达到验收标准 |
| 8 | 导出 | 原始文件不动，结果另存 |

## 5. 验收标准（已写成 assert）

- [x] 原始文件的 SHA-256 不变
- [x] 每行都标注 `SIMULATED`
- [x] 共 60 个批次
- [x] 批次号唯一
- [x] 除取消批次外，没有运行时间为 0 的行
- [x] 合格产出不超过投入
- [x] 派生指标里没有 `inf`
- [x] 有标记的行都写进了清洗日志
- [x] 行数对得上账：原始 63 行 = 现在 60 行 + 日志里删除的 3 行
- [x] 问题清单里的每个问题，都按第 3 项计划的方式处理了（和清洗日志逐条对账）

## 6. 产出物

| 清洗日志 | `data/cleaning_log.csv`（9 条） |
| 清洗脚本 | `clean_batches.py`（`--step N` 可以停在任意一步） |

## 7. 审阅与更新
